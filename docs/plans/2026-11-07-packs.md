# Packs and Rebirths Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Players roll free packs every 3 seconds, open them for 3 cards with a reveal, rebirth for luck, and see their income in the Outpost.

**Architecture:** Every rule is pure and lives in `src/shared/CardCore/` (`Packs`, `Rebirth`, `PackText`), tested in Lune. `src/server/PackServer.luau` holds the remotes, timers and auto loops, and `src/server/Purchases.luau` holds everything Robux. On the client, `PacksPanel` is a new menu page, `PackFace` draws a wrapper, and `PullReveal` plays the reveal.

**Tech Stack:** Luau, Rojo, Lune tests, ProfileStore, Python with Pillow for the baked art.

**Spec:** `docs/specs/packs.md`

## Global Constraints

- Work from `H:\SplitDeck` on branch `feature/packs`. Bash resets its folder, so start commands with `cd /h/SplitDeck`.
- Compile check: `lune run "$S/compile_all.luau"`, the scratchpad script that parses every module. It misses undefined globals. If it has gone, write one.
- Tests: `export PATH="$HOME/.rokit/bin:$PATH"; lune run tests/run.luau`. A new `x_spec.luau` goes in both `listed` and the `require` lines of `tests/run.luau`.
- New modules go in folders Rojo already maps: `src/shared/CardCore/`, `src/shared/Guns/Hud/`, `src/client/`, `src/server/`.
- Tier ids stay `Field`, `BlackSite`, `Prototype`. The player sees `BlackSite` as `REDLINE`. Zero-Day is a variant on cards and a fourth pack id, `ZeroDay`.
- Menu text uses image fonts with A-Z 0-9 / : . - > + _ only. There's no `%`, comma or apostrophe.
- Menus are Bone paper with Deep Navy ink. Use `PanelKit`, and sizes as shares of `MenuPanel.unit()`.
- The server holds every result and the roll timer. Nothing the client sends is trusted, except the favorite, which the spec accepts.
- River does all Play testing. Never start Play through tools, and never edit scripts through Studio.
- Never commit `assets/`, place files or API keys.
- Odds and prices live in `Config.luau`, so they're easy to tune.

## Decisions the spec left open

- **Luck past 100%:** if the raised rare outcomes add up to more than 1, they're scaled down evenly to total 1 and the commonest outcome is 0.
- **Open All with an empty pile:** Auto Open can empty the pile while the prompt is up. The purchase is then saved as `openAllCredits`, and the next `OPEN ALL` click spends it without a prompt, so 1,500 Robux is never lost.
- **Auto roll on or off:** a session choice, off on join. It isn't saved.
- **Auto Open:** always on for owners.
- **Paid odds:** an `ODDS` button shows the card odds as well as the pack odds, because Open All sells random items.
- **Rebirth safety:** it takes all Credits, so the button needs a second click, `CONFIRM`.
- **Face-down cards:** `CardFace.back` names the card, so the reveal uses a plain back in the pack's colours.

## Review Focus

1. A pile or stack reaching `MaxStackCount`: `SaveData` deletes any stack above the cap on load, so nothing may ever pass it, and rolling stops with `PileFull`.
2. Very high rebirth counts: every odds table still totals 1 with no negative chance.
3. Open All bought while the pile is empty, or Auto Open racing the prompt: the purchase is kept, never lost.
4. A repeated receipt, or one arriving after the player left: nothing opens twice, and the receipt stays pending until the data is loaded.
5. Open All on a pile of a million packs: one server step, a result small enough to send, and no per-card table.
