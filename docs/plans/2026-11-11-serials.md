# Serials Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give every pulled card a real, never-repeated serial, stored compactly, with the full save reset River chose.

**Architecture:** `data.stacks` keeps meaning "how many copies" so income, deck power, decks and the index don't change. A new `data.serials` table beside it records, per stack, the numbered copies as runs and the starter copies as a count; copies that are neither are "waiting". A server loop asks one shared DataStore counter for numbers every 5 seconds and writes them into saves. The client is told each stack's lowest serial, and each pulled card's own serial when it arrives.

**Tech Stack:** Luau (Roblox, Rojo), ProfileStore saves, DataStoreService `UpdateAsync`, Lune tests.

**Spec:** `docs/specs/serials.md` (read it first). How a serial looks is `docs/specs/card-face-redesign.md`.

## Review Focus

1. A player fuses or leaves between the batch asking for numbers and getting them: fewer copies are waiting than numbers came back. The extra numbers are skipped; no count goes negative and nothing errors.
2. The counter can't be reached: no save changes, copies stay waiting, the next batch asks again.
3. A save whose runs are damaged (overlapping, backwards, more numbered copies than the stack holds, wrong types) loads without error and without a duplicated serial.
4. Open All on a pile of a million: one run per stack, no per-copy loop anywhere on the path.
5. A stack made only of starter copies shows `----`, reports no lowest serial and is never numbered by a batch.

Tests for 1, 2, 3 and 5 are in Tasks 1 to 3. Number 4 is a test in Task 1 that numbers and removes a million copies and must finish at once.

### Task 1: Runs in `Inventory`

**Files:**
- Modify: `src/shared/CardCore/Inventory.luau`
- Test: `tests/inventory_spec.luau` (extend if it exists, else create and add to both lists in `tests/run.luau`)

**Interfaces:**
- `data.serials: { [key]: { runs: { number }, plain: number } }`. `runs` is a flat list of pairs, `{ from1, to1, from2, to2 }`, sorted, never touching or overlapping. An entry is removed when it has no runs and `plain` is 0. Code must treat a missing `data.serials` as empty.
- Unchanged: `Inventory.key`, `parse`, `count`, `ownsCard`, and `add(data, cardId, tier, variant, n)` (adds waiting copies).
- New:
  - `Inventory.addPlain(data, cardId: string, tier: string, variant: string, n: number)` — adds starter copies.
  - `Inventory.waiting(data, key: string): number` — stack count minus numbered minus plain, never below 0.
  - `Inventory.number(data, key: string, from: number, to: number): number` — gives waiting copies the serials `from` upward and returns how many it used, at most the number waiting. Joins runs that touch.
  - `Inventory.lowest(data, key: string): number?`
  - `Inventory.take(data, key: string, serial: number): boolean` — removes exactly that numbered copy, splitting its run. False if not owned.
- Changed: `Inventory.remove(data, cardId, tier, variant, n): boolean` spends starter copies first, then waiting, then the highest serials.

it("uses only as many numbers as copies are waiting", function() -- Review Focus 1
	Inventory.add(data, "phase_dash", "Field", "Base", 2)

	expect(Inventory.number(data, key, 20, 29)).toBe(0)

it("joins runs that touch and keeps them sorted", function()

it("clears a stack's record when the last copy goes", function()

	Inventory.number(data, key, 4, 4)

	expect(data.serials[key]).toBe(nil)
end)
it("never numbers starter copies", function() -- Review Focus 5

	expect(Inventory.waiting(data, key)).toBe(0)
	expect(Inventory.number(data, key, 1, 3)).toBe(0)
	expect(Inventory.lowest(data, key)).toBe(nil)
end)
it("handles a million copies without visiting each one", function() -- Review Focus 4

it("works on a save with no serials table yet", function()

### Task 3: The batch rules

**Files:**
- Create: `src/shared/CardCore/SerialBatch.luau`
- Test: `tests/serialbatch_spec.luau` (add to both lists in `tests/run.luau`)

**Interfaces:**
- Consumes: `Inventory.waiting`, `Inventory.number`.
- Produces (all pure):
  - `SerialBatch.wanted(data): { [string]: number }` — waiting copies per stack key; stacks with none are left out.
  - `SerialBatch.total(wants: { { [string]: number } }): { [string]: number }` — the sum per key over several players.
  - `SerialBatch.reserve(counters: { [string]: number }, total: { [string]: number }): ({ [string]: number }, { [string]: number })` — returns the new counters and the first serial for each key. A key not yet in `counters` starts at 1. Doesn't change its arguments.
  - `SerialBatch.apply(data, key: string, first: number, share: number): (number, number?, number?)` — numbers up to `share` waiting copies from `first`; returns how many it used and the first and last serial it gave (nil when none).
  - `SerialBatch.queue()` returns a per-player pull queue with `queue:push(key: string, openId: number, slot: number)` and `queue:assign(key: string, from: number, to: number): { { openId: number, slot: number, serial: number } }` — hands serials to that key's waiting pulls, oldest first, and drops them from the queue. Pulls beyond the serials stay queued.

- [ ] **Step 1: Write the failing tests:**
  - `wanted` on a save with a stack of 5 holding 2 numbered and 1 plain gives `{ [key] = 2 }`, and leaves out a fully numbered stack and an all-starter stack.
  - `total({ { a = 2 }, { a = 3, b = 1 } })` gives `{ a = 5, b = 1 }`.
  - `reserve({ a = 10 }, { a = 5, b = 1 })` gives counters `{ a = 15, b = 1 }` and firsts `{ a = 11, b = 1 }`, and the table passed in still has `a = 10`.
  - Two players wanting 2 and 3 of `a` from first 11: `apply(one, "a", 11, 2)` returns `2, 11, 12`; `apply(two, "a", 13, 3)` returns `3, 13, 15`; no serial appears in both saves.
  - Review Focus 1: a save with 1 waiting, `apply(data, key, 20, 4)` returns `1, 20, 20`; with 0 waiting returns `0, nil, nil`.
  - Queue: push `(key, 1, 1)`, `(key, 1, 3)`, `(key, 2, 2)`; `assign(key, 50, 51)` returns open 1 slot 1 → 50 and open 1 slot 3 → 51; a second `assign(key, 60, 60)` returns open 2 slot 2 → 60; a third returns an empty list. `assign` for a key never pushed returns an empty list.

### Task 4: The counter and the batch loop

**Files:**
- Create: `src/server/SerialCounter.luau`, `src/server/SerialServer.luau`
- Modify: `src/server/PlayerCards.luau` (snapshot), `src/server/PackServer.luau` (open ids and the serials event), `src/server/CardCore.server.luau` (start the loop where the other server modules start)

**Interfaces:**
- Consumes: Task 3's `SerialBatch`, `PlayerCards.get/changed/loaded/profileLoaded`.
- `SerialCounter.reserve(total: { [string]: number }): { [string]: number }?` — yields. One `UpdateAsync` on DataStore `SerialCounters_v1`, key `all`, whose callback is `SerialBatch.reserve` on the stored table (an empty table when nothing is stored). Returns the firsts, or nil if the call failed. Wrapped in `pcall`. When the DataStore can't be used in Studio (the same check `ProfileComments.luau` makes), it keeps the counters in a module table instead. Comment: if this one record ever becomes a bottleneck, split it per card here; nothing else knows its shape.
- `SerialServer.start()` — every 5 seconds: for each loaded player take `SerialBatch.wanted`; skip the round if nobody wants anything; `SerialCounter.reserve` the total; on nil do nothing this round; otherwise walk the players in the order the wants were taken, giving each its share from a running first per key through `SerialBatch.apply`, but only if the player's profile is still loaded (re-read it with `PlayerCards.get` after the yield); then `PlayerCards.changed(player)` and report pull serials. Only one round runs at a time.
- `SerialServer.pulled(player: Player, openId: number, cards: { { cardId: string, tier: string, variant: string } })` — queues each card's slot for the serials message. `PackServer` calls it after each single-pack open, with an `openId` it counts per player and also puts in the open event it already sends. Open All doesn't call it.
- When a round numbers a player's queued pulls, the server sends on the existing pack event: `{ type = "Serials", openId = number, serials = { [slot] = serial } }`, one message per open.
- `PlayerCards.snapshot` gains `lowest: { [string]: number }`: `Inventory.lowest` for every stack that has one.
- A player's queue is dropped when they leave.
